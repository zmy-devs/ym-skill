# 通用代码与 TypeScript

适用于本次新增或修改的 JS/TS 代码；框架专属写法再叠加相应资料。

## 命名与写法

- 优先 TypeScript；既有 JavaScript 项目保持现状，不为局部改动迁移语言。
- 自建文件和目录默认短横线命名：`order-summary.tsx`、`order-summary.vue`、`use-order.ts`。框架保留文件名和仓库已有约定优先，不批量重命名。
- 变量和函数用小驼峰，组件标识符和类型用帕斯卡命名。事件处理函数以 `handle` 开头，业务函数直接表达行为，如 `updateResourceStatus`；不把文件名、模块名和完整业务流程重复塞进函数名。
- 优先 `const`，默认不用 `var`；确实需要重新赋值时使用 `let`，不为消灭 `let` 写更复杂的表达式。
- 普通函数和回调偏好箭头函数；生成器、重载和动态 `this` 等按语言需要使用 `function`。简单表达式可直接返回，多语句体使用代码块并显式 `return`。
- 独立语句或声明之间空一行；一条多行语句内部不额外拆开。`if` / `else if` / `else` 一律使用花括号；格式与项目工具冲突时服从工具。
- 偏好纯函数和明确的数据转换，不直接修改传入的共享数据。使用 `map` / `filter` 等表达转换，但不把清楚的分支或循环硬改成难读的 `reduce`。

## 控制流与可读性

- 无效输入、错误和退出条件尽早返回，避免多层嵌套。
- 禁止嵌套三元。单层三元只表达简单的值选择或短小 UI 分支；API 调用、状态转换、权限流程和多步骤业务使用 `if` + `return` 或 `switch`。
- 对互斥状态使用清楚的统一分支；独立布尔条件可以各自判断，不为了统一写法把它们改成互斥。
- 深层查值、动态 key、空值回退叠在一起难以理解时，提取有业务含义的中间值。不仅为了少几行而压缩表达式，也不为简单表达式制造无用变量。
- 异步调用按调用关系 `await`、返回 Promise 或处理 rejection。不用 `void` 前缀忽略结果，不能只删除 `void` 后留下未处理的 Promise；不要用空 `catch` 吞掉失败。

```ts
// 选中资源对应的草稿键，未选中时不查询
const draftKey = resource ? getDraftKey(category, resource.id, locale) : null;

// 当前草稿，缺省时显示空表单
const values = draftKey === null ? {} : (drafts[draftKey] ?? {});
```

## 中文注释

- 保留个人习惯：为本次新增或修改的函数、组件和数据声明添加简短中文 `//` 注释；函数说明职责，数据说明用途、来源或计算规则，即使声明是简单赋值也适用。
- 不逐个注释 import、函数参数、内联回调参数和类型字段；一条解构声明整体注释即可。不为凑注释解释语法或重复变量名。
- 新写的说明默认不用 `/** */`；项目要求的工具指令、许可证和 API 文档按项目约定保留。不要为了补注释改动无关代码。

## 类型边界

- 共享或复杂业务模型放到项目已有类型模块；项目无约定时用功能目录下的 `types.ts` 或共享 `types/`。不要在组件函数体内反复定义业务模型，也不把所有局部类型集中成全局大文件。
- 简短且只服务当前组件的 Props / Emits 可与组件同文件，在 React 组件外定义；Vue 编译器宏的内联规则见 Vue 资料。优先复用已有契约，避免重复定义。
- 类型能推断时不重复标注变量类型、函数返回类型或泛型；公开契约、重载、联合类型初始值等需要时显式声明。
- 不新增用来逃避检查的 `any`、无依据的断言、非空断言或 `@ts-ignore`。不确定的外部数据用 `unknown` 并在边界收窄；第三方 API 的必要例外说明原因，不扩散到业务数据。
- 编译通过不代表外部输入已经有效；使用项目现有方式验证接口、存储或 URL 中的不可信数据，不另加一套无关校验体系。

## 清理

- 清理本次改动造成或涉及的 unused import、变量、函数、类型、state、调试输出和失效注释，不保留“以后可能用”的 helper 或注释代码。
- 只在确认真实默认行为和使用位置后删除冗余属性，例如已验证默认一致的 `variant='default'`、`type='text'`。原生按钮与封装按钮的默认值不能混为一谈。
- 必要的表单按钮类型、可访问名称、焦点管理、受控状态和业务意图都不是噪声；具体判断见元素结构和组件设计资料。
