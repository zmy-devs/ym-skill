# YM 前端开发与自审规范

## 工作边界

- 用户当前明确要求优先；遵守目标仓库说明、现有技术栈、框架版本和 lint/格式化配置。个人偏好只在不冲突时应用，不为满足偏好迁移技术栈或增加依赖。
- 只处理本次需求和受影响的调用方，不顺带整理全仓、批量补注释、移动类型或重新格式化无关文件。
- 命名、中文注释、空行、箭头函数、Vue 的 `ref` 偏好和类名顺序属于个人约定；不能用它们覆盖运行正确性、框架规则和真实交互需求。
- 这是本地指令型技能，不依赖 OO、MCP 或专用脚本；使用目标项目已有工具验证。

## 先判断任务，再读取资料

先看仓库说明、依赖与版本、相邻实现和当前 diff，确认实际使用的框架、组件库和任务范围。仓库有 `.codegraph/` 时，理解或定位代码先用 CodeGraph；不存在则跳过。

不要一次性加载全部资料。按下表读取当前任务涉及的文件；React 与 Vue 规则不互相套用，未使用 Tailwind 或 shadcn/ui 时不引入它们。

## 编写与修改

1. 复用现有能力，按已读取的规范实现需求。先确定数据流、状态和组件职责，再写界面；不先堆代码再指望审查清单兜底。
2. 保持逻辑、模板和样式可直接理解；需要拆分时围绕真实职责，不按行数或文件数机械拆分。
3. 完成后进入下面的自审流程；自审是这次实现的一部分，不必等用户再次要求。

## 自审与独立 review

- **编写或修改后的自审**：读取 `references/review.md`，审查自己的最终改动，直接修复范围内的问题，再复查和验证；不能仅输出问题清单。
- **审查并修复**：用户要求“review 并修复”“按规范整理”时，先确认审查范围，再执行同样的修复闭环。
- **只审查**：用户仅要求审查，或明确说“只 review / 不修改”时，只输出有证据的问题和验证情况，不修改代码。不要因技能包含自动修复就覆盖用户的只读意图。
- 默认审查本次 diff，包括任务内的新文件；读取直接相关的完整函数、组件及调用方来核实行为。用户指定文件、commit 或分支范围时使用该范围。
- Critical / High 问题未解决不能声称通过；遇到缺少权限、依赖、服务或必须由用户决定的问题时，明确报告阻塞和未通过，不反复盲改或伪造结果。

## 交付

默认用中文，先给结果，简短说明变更、实际验证和未解决事项。实现任务附上精简审查结果；仅审查时优先列问题，具体格式见审查资料。未执行的检查必须写明，不能用“已通过”代替。
